AnthroForge crowd demo — Windows quick start
=============================================

1. Unzip this whole folder somewhere (keep the folder structure intact —
   the .html files find everything else by relative path).

2. Double-click "start_demo.bat".
   - It looks for Python (as "py" or "python") and uses that to run a
     tiny local web server. Most Windows installs have this via the
     Microsoft Store / python.org installer.
   - If you don't have Python but do have Node.js, it falls back to
     `npx serve` automatically.
   - You MUST use this server — double-clicking the .html file directly
     will NOT work (Chrome/Edge block a page opened as file:// from
     fetching other local files, which this demo needs to do to load
     the character pack).

3. Once the window says something like "Serving HTTP on 0.0.0.0 port
   8000", open your browser to:

     http://localhost:8000/packages/web/demo/crowd.html

   for the crowd demo (type a number of humans, hit Generate — they'll
   idle / walk / run / wave on a ground plane), or:

     http://localhost:8000/packages/web/demo/diversity.html

   for the simpler 4x4 grid of 16 differently-shaped characters, or:

     http://localhost:8000/packages/web/demo/crowd_dance.html

   for the dance crowd: generated humans dancing to 16 real motion-capture
   clips (Hip Hop, House, Thriller, Robot, Swing, Rumba, breakdance moves,
   ...). Pick a dance (or "Random per character"), a headcount, hit Generate.
   Changing the dance re-choreographs the same crowd with a cross-fade.
   Each body gets its own fitted skeleton, so tall/short/wide/narrow dancers
   all move correctly. The header comment of crowd_dance.html explains the
   three problems the earlier version had and how they were fixed.

4. To stop the server, close the black command-window (or press Ctrl+C
   in it).

What's in here
---------------
packages/web/demo/crowd.html        - the sine-wave crowd/action demo
packages/web/demo/crowd_dance.html  - the NEW mocap dance crowd demo
packages/web/demo/diversity.html    - the 16-character grid demo
packages/web/demo/vendor/three/...  - three.js + OrbitControls (vendored
                                       locally so this works fully offline,
                                       no CDN needed)
packages/web/dist/                  - the engine's JS + WebAssembly build
rust-core/dance_clips/               - the 16 dance clips, retargeted onto this
                                       engine's skeleton (dance_clips.json =
                                       index, dance_clips.bin = 30 fps joint
                                       rotations)
packages/web/demo/dance/pose.js      - clip sampling / cross-fading / per-body
                                       root + floor handling
packages/web/demo/dance/skeleton_fit.js - fits the engine's single skeleton to
                                       each generated body
tools/                               - offline tools that produced the clips
                                       (see tools section below)
packages/web-three/dist/           - helper that turns a generated
                                      character into a real three.js mesh
rust-core/packs/                   - essentials.afpp (the actual body/face
                                      part + morph data, ~33MB) and its
                                      manifest/morph-id files

Important honesty note
-----------------------
This engine has no animation clips and no bone names anywhere in its
data or API. The walking/running/waving you'll see is 100% procedurally
generated by crowd.html: it works out which skeleton joints are "a
thigh", "a knee", "an upper arm" etc. purely by analyzing joint
positions (verified against the real skeleton with a Node script before
this was built), then swings them with sine waves. I built and
math-checked this without ever being able to open a real browser myself
(no GPU/browser available in the sandbox I built it in), so if something
looks off — legs twisting instead of swinging, or characters walking
backwards relative to which way they're facing — tell me exactly what
you see and I can very likely fix it in one pass. The two most likely
culprits are called out as tunable constants (BEND_AXIS and
FORWARD_SIGN) right near the top of crowd.html's <script> block.


Rebuilding the dance data (only needed if you change the clips)
----------------------------------------------------------------
Needs Node.js 20+ and the Mixamo .fbx files (not stored in this repo):

  cd tools && npm install
  node dump_skeleton.mjs skeleton.json
  node bake_dance.mjs <folder with .fbx files> skeleton.json ../rust-core/dance_clips

bake_dance.mjs retargets full 3D bone rotations (matching each bone's
direction, so Mixamo's T-pose vs this engine's A-pose doesn't twist limbs),
removes root drift, and stores clip metadata (groove / power move / pose).
